# 1.1 Create API Module Structure

## Objective
Set up a new Maven module `wos-api` with proper package structure, dependencies, and build configuration.

## Duration
**2-3 hours**

## Prerequisites
- Maven installed
- Access to project root POM
- Understanding of Maven multi-module structure

---

## Step-by-Step Instructions

### 1. Create Module Directory
```bash
cd wosbot
mkdir wos-api
cd wos-api
mkdir -p src/main/java/cl/camodev/wosbot/api
mkdir -p src/main/resources
mkdir -p src/test/java/cl/camodev/wosbot/api
```

### 2. Create `wos-api/pom.xml`

```xml
<project xmlns="http://maven.apache.org/POM/4.0.0"

        </dependency>

            <groupId>io.jsonwebtoken</groupId>

        </dependency>
        <dependency>
            <groupId>io.jsonwebtoken</groupId>
            <artifactId>jjwt-jackson</artifactId>
            <version>0.11.5</version>
            <scope>runtime</scope>
        </dependency>

        <!-- Monitoring and Metrics -->

            <groupId>org.bouncycastle</groupId>

        <plugins>

```

### 3. Update Parent POM

Edit `wosbot/pom.xml` to add the new module:

```xml
<modules>
    <module>wos-hmi</module>
    <module>wos-serv</module>
    <module>wos-ot</module>
    <module>wos-persistence</module>
    <module>wos-utiles</module>
    <module>wos-api</module> <!-- ADD THIS -->
</modules>
```

### 4. Create Package Structure

```bash
cd wos-api/src/main/java/cl/camodev/wosbot/api
mkdir client      # WebSocket client (for UI)
mkdir server      # WebSocket server (for backend)
mkdir protocol    # Command/Event/Response classes
mkdir service     # BotApiService facade
mkdir exception   # Custom exceptions
```

**Final structure:**
```
wos-api/
├── pom.xml
└── src/
    ├── main/
    │   ├── java/cl/camodev/wosbot/api/
    │   │   ├── client/       # UI WebSocket client
    │   │   ├── server/       # Backend WebSocket server
    │   │   ├── protocol/     # Message definitions
    │   │   ├── service/      # Service facade
    │   │   └── exception/    # Custom exceptions
    │   └── resources/
    │       └── api-config.properties
    └── test/
        └── java/cl/camodev/wosbot/api/
```

### 5. Create Configuration File

Create `src/main/resources/api-config.properties`:

```properties
# WebSocket Server Configuration
websocket.server.port=8765
websocket.server.host=localhost
websocket.server.path=/bot

# Timeouts (milliseconds)
websocket.command.timeout=30000
websocket.ping.interval=30000

# Limits
websocket.max.connections=10
websocket.max.message.size=1048576
```

### Build Scope and Execution

All Maven commands in this plan should run inside the `wos-api` module. Either `cd wos-api` before invoking Maven or keep executing from the parent while adding `-pl wos-api` so that Maven does not try to compile the other modules (their artifacts are not available yet). This keeps the iteration fast and avoids missing-artifact failures.

### 6. Verify Build

```bash
cd wosbot
mvn -pl wos-api clean install -DskipTests
```

**Expected output:**
```
[INFO] ------------------------------------------------------------------------
[INFO] Reactor Summary:
[INFO]
[INFO] wos-api ............................................ SUCCESS
[INFO] ------------------------------------------------------------------------
[INFO] BUILD SUCCESS
[INFO] ------------------------------------------------------------------------
```

## Troubleshooting

### Build fails with "Cannot resolve wos-api"
**Solution:** Run `mvn -pl wos-api clean install` from the parent directory or `cd wos-api && mvn clean install`; this keeps the build scoped to the API module whose artifacts already exist.

### Dependency version conflicts
**Solution:** Check parent POM's `<dependencyManagement>` section for version overrides.

### Package structure not recognized
**Solution:** Refresh Maven in IDE (IntelliJ: Right-click pom.xml → Maven → Reload Project)
